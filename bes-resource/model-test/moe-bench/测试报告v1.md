# Qwen1.5-MoE-A2.7B 并行模式推理性能测试报告

## 一、测试概述

在 4 张昇腾 910B4（32GB）NPU（davinci 0/1/2/3）上，对比 **Qwen1.5-MoE-A2.7B**（Qwen2MoeForCausalLM，60 专家 / top-4，约 14.3B 参数，bf16）在三种并行模式下的推理性能。一次只启动一种模式，跑完停止再起下一个。

| 项目 | 值 |
|------|-----|
| 模型 | `/home/publicmodel/Qwen1.5-MoE-A2.7B` |
| 镜像 | `vllm-ascend-0.20.2rc:offline`（vLLM 0.20.2 + vllm-ascend 0.20.2rc2） |
| 硬件 | 4×910B4 32GB（卡 0-3） |
| max-model-len | 8192 |
| gpu-memory-utilization | 0.9 |
| 压测工具 | `vllm bench serve`，`--dataset-name random` |
| 负载 | 输入 1024 tok / 输出 256 tok，走 `/v1/completions` |
| 并发档位 | 1（延迟）/ 16 / 64（吞吐），请求数 30 / 160 / 256 |

### 三种模式

| 模式 | 参数 | 说明 |
|------|------|------|
| **① TP4+EP**（窄 EP，低延迟首选） | `-tp 4 -dp 1 --enable-expert-parallel` | 单实例，attention TP=4，专家 EP 切到 4 卡 |
| **② DP4+EP**（宽 EP，高吞吐首选） | `-tp 1 -dp 4 --enable-expert-parallel` | 4 个 DP 副本各占 1 卡，专家 EP 分布 4 卡 |
| **③ 纯 TP4**（对照基准，不推荐生产） | `-tp 4`（无 EP） | attention 与专家均按 TP=4 切分 |

## 三、分析与结论

### 1. 低并发/延迟敏感场景 → 选 ① TP4+EP
- 并发 1 时 **P99 TTFT 仅 140ms**，而 ②③ 出现 3.8~4.1s 的长尾（首请求预热 + DP 侧调度抖动）。
- 单请求把 4 卡算力用满，首 token 延迟最稳，输出吞吐也最高（53 tok/s）。
- **符合预期：窄 EP 是低延迟首选。**

### 2. 高并发/吞吐场景 → 选 ② DP4+EP
- 并发 64 时 **总吞吐 9689 tok/s（最高）**，比 ① 高约 3.9%，比 ③ 高约 3.7%。
- 更关键的是**尾延迟最优**：P99 TTFT 1.22s（① 1.99s / ③ 1.92s），P99 E2EL 也最低。
- 4 路 DP 副本独立处理请求流，高并发下负载更均衡。
- **符合预期：宽 EP 是高吞吐首选。**

### 3. 纯 TP4（③）确实只适合当基准
- 各并发档位性能几乎全面被 ①/② 覆盖或持平，没有任何一项领先。
- 说明该 MoE 模型上 **开启 EP 基本无负收益**：低并发靠 EP+TP 拿延迟，高并发靠 DP+EP 拿吞吐；纯 TP 两头不占。
- **符合预期：仅作对照，不推荐生产。**

### 4. 交叉点观察
- 并发 16 是过渡区：① 吞吐略优且尾延迟明显更好（P99 TTFT 880ms vs 2800ms+），此负载下 ① 仍是稳妥选择。
- 并发从 16→64，② 的优势才显现（吞吐反超、尾延迟压到最低）。**真正需要上 DP4 的临界点在并发 ≳ 32~64。**

### 推荐

| 生产场景 | 推荐模式 |
|----------|----------|
| 在线对话、低延迟、并发 ≤ ~16 | **① TP4+EP** |
| 批量/高并发（≳32~64）、追求吞吐与稳定尾延迟 | **② DP4+EP** |
| 性能对照基准 | ③ 纯 TP4（不上生产） |

## 五、备注

- 测试期间卡 4-7 被另一容器（`vllm-qwen3-p`）占用，本测试全程仅用卡 0-3，互不影响。
- 该模型为 **base（非 Chat）版**，故用 `/v1/completions` 压测；性能指标与文本质量无关，对比公平。
- 数值为单次测量，存在 ±5% 波动；如需更严谨可多轮取均值。测试日期：2026-07-02。
